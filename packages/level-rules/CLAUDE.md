# level-rules rules

## The judgement

- Keep every check a pure function over the six facts of a built level: the typed
  description, the typed level, the GLB inspection, the base stage's image count, the
  prepared static level and the static objects with the boxes `level-pipeline` placed.
  Read no file, run no level preparation and place no static object.
- Judge the outcome of sec-111's preparation; copy none of sec-111's numbers.
- Spell each finding's rule id, subject and message as the level format document states
  them. Decide by the rule id, never by the message text.
- Compare every length limit with `LENGTH_SLACK` and render every length of a message with
  `formatLength`, both of `@level-designer/level-format`; hold no copy of either.

## The dependencies

- Build a slab's destruction lib model only with `slab-model`'s shared builder, and reach
  destruction lib only through `destruction-gateway`.
- Read a slab's box and a static object's class through `level-format`, the floor under a
  point through `sec111-gateway` and the GLB facts as `level-glb` types them.
- Never let a page import this component: it reaches destruction lib, whose Rapier copy
  must not meet sec-111's in a page bundle.

## The tests

- Test on sec-111's committed prepared level through the gateway's testing entry or on a
  hand-built box room. Never prepare a level in a test; `level-pipeline` owns the
  preparations.
